# Как получить ключи приложений (OAuth 2.0)

Программа работает с двумя облаками. Для «Моего диска» нужны ключи
приложения, для чужих публичных ссылок — **не нужны** (их можно открыть
сразу, без входа).

| | Яндекс.Диск | Google Диск |
|---|---|---|
| Где смотреть | https://oauth.yandex.com/ | https://console.cloud.google.com/apis/credentials |
| Куда вписать | Настройки → «Доступ к облакам» | Настройки → «Доступ к облакам» |

Инструкция ниже — для администратора, который один раз заводит ключи
и раздаёт их монтажёрам.

---

## 1. Яндекс.Диск

### 1.1. Создать приложение

1. Откройте <https://oauth.yandex.com/> (или <https://oauth.yandex.ru/client/new/>)
   и войдите под **тем аккаунтом разработчика**, который точно не потеряете:
   под ним потом проходит проверка приложения.
2. Нажмите **«Создать приложение»** → в окне выбора типа выберите
   **«Для доступа к API или отладки»** (For API access or debugging).
   * Тип приложения выбирается один раз и потом не меняется — это нормально:
   нашему приложению нужно обращаться к API Диска, а не к профилю Яндекс ID.
3. Заполните:
   * **Название сервиса** — `svsCloud`;
   * **Контактный email** — реальный почтовый ящик (на него придут
     уведомления о проверке приложения);
   * **Права доступа** — включите **«Чтение всех файлов Яндекс.Диска»**
     (в API это scope `cloud_api:disk.read`). Запись нам не нужна.
4. Нажмите **«Создать»**.

> **Про Redirect URI.** У приложений типа «Для доступа к API» redirect URI
> задан жёстко и не редактируется: `https://oauth.yandex.com/verification_code`.
> Именно на эту страницу Яндекс отправляет пользователя, показав код
> подтверждения. Ничего регистрировать не нужно — но если вы создавали
> приложение раньше, проверьте, что в поле «Redirect URI» (платформа
> «Веб-сервисы») стоит именно `https://oauth.yandex.com/verification_code`.

### 1.2. Забрать ключи

На странице приложения есть:

* **Client ID** (он же «Идентификатор приложения») → `yandex_client_id`
* **Client Secret** (он же «Пароль приложения») → `yandex_client_secret`

Проверить, какие права реально выданы, можно на странице
<https://oauth.yandex.com/client/<client_id>/info>.

### 1.3. Как проходит вход

1. В программе: «Аккаунты» → «Войти через Яндекс.Диск».
2. Откроется браузер на странице авторизации Яндекса. Пользователь
   входит под своим аккаунтом и подтверждает доступ.
3. Яндекс показывает **код подтверждения** — строку из букв и цифр (код живёт 10 минут).
4. Пользователь копирует код; программа подставляет его из буфера обмена
   автоматически — достаточно нажать Enter.

Права токена можно отозвать в любой момент:
<https://id.yandex.com/personal/data-access>.

## 2. Google Диск

### 2.1. Создать проект

1. Откройте <https://console.cloud.google.com/>.
2. Создайте проект (например `svsCloud`).
3. **APIs & Services → Library** → найдите **Google Drive API** → **Enable**.

### 2.2. Создать OAuth-клиент

1. **APIs & Services → Credentials → Create Credentials → OAuth client ID**.
2. **Application type** → **Desktop app** (именно этот тип поддерживает
   редирект на `http://127.0.0.1:<порт>`, он и нужен настольной программе).
3. Задайте имя, нажмите **Create**.
4. Появятся:
   * **Client ID** → `google_client_id`
   * **Client secret** → `google_client_secret`

### 2.3. Разрешить вход монтажёрам

Если приложение в статусе **Testing**, войти смогут только те, кто указан
в тестовых пользователях:

1. **APIs & Services → OAuth consent screen** → **Test users** →
   **Add users** → добавьте почты всех монтажёров (обычно корпоративные).
2. Либо опубликуйте приложение: **Publish app** (для внешнего приложения
   потребуется проверка Google, для внутреннего в Workspace — достаточно
   нажать Publish).

### 2.4. API-ключ (необязательно)

**APIs & Services → Credentials → Create Credentials → API key** →
`google_api_key`.

Нужен, чтобы открывать **публичные** папки Google без входа в аккаунт.
Ограничения ключа выставьте как «не ограничивать» для Google Drive API
или добавьте в ограничения IP/Drive API.

### 2.5. Как проходит вход

Программа поднимает локальный сервер на случайном порту, открывает
системный браузер, вы согласуете доступ — программа получает код сама.
Ничего вводить не нужно.

## 3. Как раздать ключи монтажёрам

**Вариант А — через настройки программы.** Каждый монтажёр открывает
«Настройки» и вставляет Client ID / Secret. Просто, но каждый вводит руками.

**Вариант Б — централизованно (рекомендуется).** Раздайте готовый
`config.json` с ключами или задайте переменные окружения:

```powershell
setx SVSCLOUD_YANDEX_CLIENT_ID     "1234567890"
setx SVSCLOUD_YANDEX_CLIENT_SECRET "abcdef"
setx SVSCLOUD_GOOGLE_CLIENT_ID     "1234-abc.apps.googleusercontent.com"
setx SVSCLOUD_GOOGLE_CLIENT_SECRET "GOCSPX-..."
setx SVSCLOUD_GOOGLE_API_KEY       "AIza..."
```

Программа читает переменные окружения при старте и подставляет их в
настройки. Файл настроек: `%APPDATA%\svsCloud\config.json`.

## 4. Частые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| В Яндексе при входе сразу ошибка | Не задан Client ID | Настройки → «Доступ к облакам» |
| «Код введён неверно» | Вставлен не тот код (например, ссылка или старый токен) | Скопировать именно код со страницы `oauth.yandex.com/verification_code` |
| «Код не подошёл: он мог истечь» | Код живёт 10 минут | Пройти авторизацию заново |
| «У приложения нет прав на Яндекс.Диск» | В регистрации не выбрано чтение диска | <https://oauth.yandex.com/client/<client_id>/info> → добавить `cloud_api:disk.read` |
| «Ключи приложения неверны» | Опечатка в Client ID / Secret | Пересоздать ключи и вставить заново |
| Google: «Приложение не проверено» (403 access_denied) | Приложение в Testing, монтажёр не в тестовых пользователях | Добавить почту в Test users или опубликовать приложение |
| Google: 403 «Google не отдаёт этот файл напрямую» | Файл запрещён к скачиванию владельцем | Ограничение владельца. Для Google Документов используется экспорт |
| Google: ошибка при открытии публичной ссылки без входа | Нет API-ключа | Вписать `google_api_key` в настройках или войти в аккаунт |
| Токен слетел после переустановки Windows | DPAPI привязан к учётной записи и машине | Войти заново — это нормально |
