# ТЗ: НоуКо Cloud 1.0

**Статус:** черновик к согласованию  
**Дата:** 23.10.2026  
**Версия продукта:** 1.0.0  
**Платформа:** Windows 10/11 x64  
**Аудитория:** монтажёры, продюсеры, небольшие продакшены

## 1. Цель релиза

Выпустить 1.0 как стабильную, предсказуемую и «взрослую» версию: её не страшно
установить на чистую Windows, она переживает большие очереди и не даёт пропустить
новый релиз. Релиз не расширяет список облаков, а закрывает доверие, устойчивость
и ежедневный сценарий монтажёра.

Критерии успеха:

- обновление с 0.5.x не требует повторного входа и не теряет настройки, очередь
  и недокачанные файлы;
- от первого запуска до первой загрузки — не больше 3 минут без чтения документации;
- на чистой Windows 10/11 без прав администратора нет P0-дефектов и предупреждений
  SmartScreen, блокирующих запуск;
- пользователь может сам собрать диагностику и отправить её в поддержку;
- в публичном архиве и диагностике нет токенов, client secret и подписанных URL.

## 2. Границы релиза

### 2.1. Входит в 1.0 (P0)

| № | Функция | Результат |
|---|---|---|
| 1 | Уведомление об обновлении | Проверка GitHub, открытие страницы нового релиза в браузере, настройка |
| 2 | Подпись и установщик | Подписанный exe/установщик, per-user установка, portable zip |
| 3 | Выход из аккаунта | Кнопка «Выйти», подтверждение, очистка токена и кэша |
| 4 | Первый запуск | Мастер: ключи, папка загрузок, проверка, вход |
| 5 | Поиск и фильтры | Поиск по загруженному дереву, фильтры по типу |
| 6 | Повтор ошибок и диагностика | Повтор неудачных, zip с логами без секретов |
| 7 | Место и отчёт | Проверка диска, пауза при нехватке, CSV-отчёт |
| 8 | Кэш и миграции | Кэш листингов, версии config/state, бэкап |
| 9 | Превью для монтажёра | Таймкод, покадрово, J/K/L, in/out, экспорт кадра |

### 2.2. Можно добавить, если останется время (P1)

Не блокирует выпуск 1.0:

- «Скачать и выключить ПК» после завершения всей очереди;
- drag&drop ссылки в окно и автоматическое распознавание ссылки из буфера;
- прогресс загрузки в панели задач Windows;
- «Отметить все найденные» после поиска;
- контактный лист/сториборд папки через ffmpeg.

### 2.3. Не входит в 1.0

- автоматическая установка обновлений и helper-процесс (в 1.0 — только
  уведомление со ссылкой на релиз);
- новые облака (Dropbox, OneDrive, MEGA);
- несколько аккаунтов одного облака одновременно;
- Google Shared Drives;
- генерация прокси для Premiere;
- watch folder и автозагрузка новых файлов;
- AI-транскрипция и поиск по речи;
- запись в облако, переименование, удаление;
- мобильная/web-версия, плагины, публичный API.

Эти пункты — бэклог 1.1+; в 1.0 они не должны появляться «попутно».

## 3. Общие требования

- **ОС:** Windows 10 1809+ и Windows 11, только x64.
- **Права:** установка и работа без прав администратора. Установщик ставит
  программу в `%LOCALAPPDATA%\Programs\NoukoCloud`.
- **Форматы поставки:** установщик и portable-zip. Обе версии используют одни
  и те же `%APPDATA%\NoukoCloud\` для настроек, токенов, логов и кэша.
- **Один экземпляр:** поведение `single_instance` сохраняется; повторный запуск
  показывает окно уже работающей копии.
- **Фон:** закрытие окна по-прежнему сворачивает в трей, загрузки продолжаются;
  выход — только через меню трея.
- **Совместимость:** читаются конфиг, токены и `.part.json` от 0.5.x. Миграция
  выполняется один раз, идемпотентно, с бэкапом.
- **Производительность:** сетевые операции не блокируют GUI; поиск по 10 000
  загруженных узлов — до 100 мс; запуск не должен заметно замедлиться.
- **Безопасность:** токены только через DPAPI; секреты не пишутся в логи,
  диагностику и CSV; HTTPS с проверкой сертификата; подпись бинарников.
- **Приватность:** никакой автоматической телеметрии. Диагностика собирается
  только по действию пользователя и никуда не отправляется автоматически.
- **Локализация:** русский интерфейс; строки не хардкодить в новых модулях,
  чтобы 1.1 можно было перевести без переписывания.
- **Лицензии:** в поставку входят `THIRD_PARTY_NOTICES.md` и тексты лицензий
  Qt/PySide6, ffmpeg, yt-dlp; для LGPL-компонентов — ссылка на исходники.
- **Версионирование:** `app.__version__` = `1.0.0`; `config_version` и
  `state_version` увеличиваются; релизный ассет называется
  `NoukoCloud-win64.zip` (имя не менять).

## 4. Функциональные требования

### 4.1. Обновление

> **Решение от 23.10.2026.** В 1.0 входит упрощённый вариант: при запуске
> проверять GitHub Releases и один раз на версию открывать страницу релиза в
> браузере (уже реализовано, отключается в настройках). Полный сценарий ниже
> с `latest.json`, helper-процессом и откатом переносится в 1.1.

**Сейчас:** обновление ставится вручную: скачать zip с GitHub и заменить папку.
Проверка версии и переход на страницу релиза уже есть; автоматической установки
нет. В `app/main.py` есть `--quit` для закрытия запущенной копии.

**Требование (полный сценарий, 1.1):**

1. Добавить модуль `app/update/`:
   - `checker.py` — проверка версии и манифеста;
   - `downloader.py` — загрузка, прогресс, отмена, SHA256;
   - `installer.py` — подготовка, запуск helper-процесса, откат;
   - `manifest.py` — разбор и валидация `latest.json`.
2. Публиковать в GitHub Release три ассета:
   - `NoukoCloud-win64.zip` — как сейчас;
   - `NoukoCloud-win64.zip.sha256` — только хеш;
   - `latest.json` — версия, дата, заметки, размер, SHA256, `min_version`,
     `mandatory`.
   Постоянный URL манифеста:
   `https://github.com/peeppohui/NouKoCloud/releases/latest/download/latest.json`.
   Запросы выполнять с `follow_redirects=True` (как в `publish_release.py`).
3. Проверять обновления:
   - через 10 секунд после показа главного окна;
   - не чаще одного раза в 24 часа;
   - вручную из «Настройки → О программе» и из уведомления;
   - настройка `auto_update_check` (по умолчанию `true`);
   - `skipped_version` хранит версию, которую пользователь попросил не предлагать.
4. Сравнивать версии как semver; prerelease/draft игнорировать.
5. Показывать немодальный баннер/диалог: версия, дата, размер, краткие заметки,
   кнопки «Скачать и обновить», «Позже», «Пропустить эту версию».
6. Скачивать в `%APPDATA%\NoukoCloud\updates\<version>\` с прогрессом и отменой.
   Перед распаковкой проверить:
   - размер;
   - SHA256 из `latest.json` и `.sha256`;
   - свободное место (архив + распакованная копия + запас 20%).
7. Проверять подпись нового `NoukoCloud.exe` через WinVerifyTrust. Если подпись
   не совпадает с ожидаемым издателем — обновление отменить.
8. Установка:
   - если очередь облака или соцсетей активна, предложить «Отложить до окончания»
     (по умолчанию) или «Остановить загрузки и обновить»; во втором случае
     сохранить состояние и продолжить очередь после перезапуска;
   - gracefully закрыть приложение (`--quit`), дождаться выхода;
   - отдельный подписанный helper (`NoukoCloudUpdater.exe`) ждёт PID, делает
     backup текущей папки, распаковывает staging, запускает новый exe;
   - если новый процесс не стартовал за 30 секунд или завершился с ошибкой —
     восстановить backup и показать сообщение;
   - после успешного старта backup удаляется (или хранится 7 дней);
   - `config.json` рядом с exe и данные в `%APPDATA%` не перезаписываются;
   - portable-версия, лежащая в read-only папке, не обновляется молча: показать
     путь к скачанному zip и предложить распаковать вручную.
9. Вести `logs/update.log`; в интерфейсе — состояние «Проверяем / Скачиваем /
   Готово к перезапуску / Ошибка» с кнопкой «Повторить».
10. Изменения в `tools/publish_release.py`: не удалять `latest.json` и `.sha256`
    при перезаливке релиза; генерировать оба файла после сборки zip. Имя
    `NoukoCloud-win64.zip` и постоянная ссылка `releases/latest/download/...`
    остаются неизменными.

**Ошибки и крайние случаи:**

- нет интернета / GitHub недоступен / 403 rate limit — тихо отложить проверку,
  не показывать ошибку при автопроверке; при ручной — понятное сообщение;
- SHA256 не совпал — удалить файл, предложить скачать заново;
- нет места — показать, сколько нужно и сколько есть;
- антивирус заблокировал helper — откат, сообщение с путём к zip;
- обновление поверх запущенной копии — helper обязан дождаться полного выхода;
- путь с пробелами, кириллицей, длиной > 260 символов — поддерживать.

**Приёмка:**

- с 0.5.4 на тестовую 1.0.0 обновление проходит без администратора;
- после обновления сохранены вход, настройки, очередь и `.part`;
- подмена SHA256 и подписи блокирует установку;
- сбой нового exe возвращает старую версию;
- обновление с активной очередью не теряет прогресс;
- повторная проверка в тот же день не дёргает сеть.

### 4.2. Подпись и установщик

**Сейчас:** собирается папка `dist\NoukoCloud\`, распространяется zip; подписи
нет; `build.ps1` может записать реальные OAuth-ключи в `config.json` рядом с exe,
который попадает в публичный архив.

**Требование:**

1. Приобрести сертификат подписи кода (OV или EV; EV желательнее для SmartScreen).
2. Подписывать `NoukoCloud.exe`, `NoukoCloudUpdater.exe`, установщик и
   деинсталлятор; ставить RFC3161-метку времени.
3. В `packaging/build.ps1` добавить режим `-Sign` (release) и `-SkipSign` (dev).
   В release-сборке ошибка подписи должна останавливать сборку.
4. Сделать установщик (Inno Setup или WiX/MSIX) с per-user установкой:
   - `%LOCALAPPDATA%\Programs\NoukoCloud`;
   - ярлык в меню «Пуск», опционально на рабочем столе;
   - деинсталлятор;
   - при удалении по умолчанию не удалять `%APPDATA%\NoukoCloud` и папку
     загрузок; предложить очистку отдельным чекбоксом;
   - не требовать UAC.
5. Публичный релиз не должен содержать реальные `client_secret`. Ключи для
   публичной сборки либо пустые (мастер первого запуска), либо передаются
   через защищённые переменные CI и не попадают в zip. Для приватной сборки
   заказчика допускается отдельный `config.local.json`, который не входит в
   публичный архив.
6. Публиковать `SHA256` рядом с архивом и установщиком; добавить в релиз
   `THIRD_PARTY_NOTICES.md`.
7. Отправить установщик в Microsoft для проверки SmartScreen; вести инструкцию
   «что делать, если Windows показала предупреждение».

**Приёмка:**

- `signtool verify /pa` подтверждает подпись exe и установщика;
- установка/удаление без администратора;
- после удаления настройки и загрузки не уничтожаются без согласия;
- публичный zip не содержит непустых секретов;
- установленная версия обновляется тем же механизмом, что portable.

### 4.3. Выход из аккаунта и смена аккаунта

**Сейчас:** в `AuthDialog` можно войти, но нельзя выйти; выход — только
`NoukoCloud.exe --reset-tokens`, который удаляет токены обоих провайдеров.
`OAuthManager.logout(pid)` уже существует (`app/oauth/manager.py:163`).

**Требование:**

1. В карточке каждого провайдера в `AuthDialog` показывать:
   - имя аккаунта и статус «вы вошли»;
   - кнопку «Выйти»;
   - кнопку «Сменить аккаунт» (то же, что выход + повторный вход).
2. Перед выходом — подтверждение: «Выйти из Яндекс.Диска? Скачанные файлы
   останутся. Токен будет удалён с этого компьютера».
3. Если для этого провайдера есть активные задания (`QUEUED`, `RUNNING`,
   `PAUSED`), предложить:
   - «Не выходить» (по умолчанию);
   - «Остановить задания и выйти» — отменить/поставить на паузу и сохранить
     состояние.
4. После подтверждения:
   - вызвать `oauth.logout(pid)`;
   - удалить токен из DPAPI-хранилища;
   - очистить `MetadataCache` для провайдера. Учесть, что текущий
     `MetadataCache.clear(provider)` удаляет ещё и все `links`; для выхода
     нужен отдельный `clear_entries(provider)` или исправленный `clear`,
     который не трогает ссылки другого провайдера;
   - убрать из дерева OAuth-корни и содержимое «Моего диска» этого провайдера;
   - публичные ссылки, уже открытые без входа, оставить, но при ошибке доступа
     показать «Войдите в аккаунт»;
   - обновить чипы и стартовый экран.
5. При истёкшем токене (401/403) не молчать: показать «Сессия истекла —
   войдите снова» и открыть `AuthDialog` по кнопке.
6. Ключи приложения в настройках не удалять автоматически; для их удаления —
   отдельное действие в «Настройках».

**Приёмка:**

- после выхода и перезапуска доступа к «Моему диску» нет;
- повторный вход работает без перезапуска;
- активная загрузка не остаётся в вечном `RUNNING`;
- токен исчез из `tokens.dat`; в логах нет значения токена;
- выход одного провайдера не ломает второй.

### 4.4. Мастер первого запуска

**Сейчас:** первый запуск сразу показывает рабочее окно; ключи и папка
настраиваются в «Настройках»; документация лежит отдельно.

**Требование:**

1. Показывать мастер, если `%APPDATA%\NoukoCloud\config.json` отсутствует или
   `first_run_completed` = `false`. Настройка сохраняется после завершения или
   явного «Пропустить».
2. Шаги:
   - **Приветствие:** что делает программа, что облако только читается.
   - **Ключи:** если ключи уже заданы portable-конфигом/переменными окружения —
     показать «Ключи уже настроены» и не раскрывать секреты; иначе поля
     Client ID/Secret для Яндекса и Google, ссылка на инструкцию. Проверка —
     формат (непустые, правдоподобная длина), без обязательного сетевого вызова.
   - **Папка загрузок:** по умолчанию `%USERPROFILE%\Downloads\NoukoCloud`;
     выбор папки, проверка записи (создать и удалить служебный файл), показ
     свободного места.
   - **Готово:** кнопки «Войти в аккаунт», «Открыть ссылку», «Начать работу»;
     чекбоксы «Запускать при входе в Windows» и «Сворачивать в трей».
3. Мастер можно пропустить; после пропуска программа остаётся работоспособной
   для публичных ссылок, но при попытке открыть «Мой диск» предлагает войти.
4. Повторно открыть мастер: «Помощь → Мастер настройки».
5. Не показывать мастер при каждом запуске, если пользователь уже настроил
   ключи вручную.

**Приёмка:**

- чистый профиль → мастер → тестовая загрузка;
- «Пропустить» → окно работает, мастер не появляется снова;
- portable-ключи не отображаются в открытом виде;
- папка только для чтения / нет места — понятная ошибка, можно выбрать другую;
- после завершения все значения совпадают с «Настройками».

### 4.5. Поиск и фильтры в дереве

**Сейчас:** дерево `FileTree` показывает загруженные узлы, поиска и фильтров
нет; сортировка своя (`TreeModel`), чекбоксы и ленивая загрузка папок уже есть.

**Требование:**

1. Над деревом — поле поиска с placeholder «Поиск по имени…», кнопка очистки
   и счётчик «Найдено: N».
2. Фильтр по типу: «Все», «Видео», «Аудио», «Фото», «Документы», «Другое».
   Группы определять по расширению и/или MIME; список расширений — общий с
   превью/загрузчиком.
3. Поиск идёт **только по уже загруженным узлам**. В неоткрытых папках не
   искать; показывать подсказку «В неоткрытых папках поиск не ищет — раскройте
   папку». Серверный рекурсивный поиск — не в 1.0.
4. Поведение:
   - регистронезависимый поиск, нормализация `ё`/`е`;
   - показывать совпавший узел и его родителей; родителей автоматически
     раскрывать;
   - не менять отмеченные чекбоксы и выбранную строку;
   - при очистке восстанавливать прежнее состояние раскрытия;
   - если ничего не найдено — «Ничего не найдено» и кнопка «Сбросить»;
   - разделы облаков и «Мой диск» не скрывать, если внутри есть совпадения;
     пустые разделы можно скрыть.
5. Клавиатура: `Ctrl+F` — фокус в поиск, `Esc` — очистить; ввод с debounce
   150–250 мс; фильтрация не должна заметно тормозить на 10 000 узлов.
6. Не ходить в сеть на каждое нажатие. Ручное «Обновить» инвалидирует кэш и
   сбрасывает фильтр только по желанию пользователя.
7. Опционально (P1): «Отметить все найденные» с подтверждением при >100 файлах.

**Приёмка:**

- поиск по части имени, кириллице и латинице;
- фильтр «Видео» оставляет видео и папки, ведущие к видео;
- отметки и очередь не меняются при поиске/очистке;
- 10 000 узлов — без зависания, <100 мс;
- поиск не делает сетевых запросов;

### 4.6. Повтор неудачных загрузок и диагностика

### 4.7. Свободное место и отчёт CSV

**Сейчас:** проверки места нет; отчёта о загрузке нет. MD5 уже проверяется в

**Требование:**

   - если размеры неизвестны: требовать минимум 1 ГиБ;

2. Во время загрузки проверять место не чаще раза в 5 секунд. Если свободно

   «Мало места на диске», не удалять `.part`; после освобождения места —
   кнопка «Продолжить».
3. Отчёт:
   - кнопка «Отчёт CSV» в очереди;

     открывал русский текст без «кракозябр»;

**Приёмка:**

- нехватка места ловится до старта и во время загрузки;
- пауза по месту не теряет `.part`;
- CSV открывается в Excel и LibreOffice, кириллица корректна;
- 0, 1 и 1000 заданий; имена с `;`, кавычками, переводом строки;
- в CSV нет секретов.

### 4.8. Кэш метаданных и миграции

**Приёмка:**

### 4.9. Превью: таймкод, покадрово, in/out, экспорт кадра

**Сейчас:** плеер умеет видео/аудио/фото, перемотку 5 сек (Shift — 1 сек),
буферизацию, `set_marks`/`play_range` для соцсетей, `videoFrameChanged`.
Таймкода, покадрового шага, J/K/L и экспорта кадра нет.

**Требование:**

1. **Таймкод.**
   - Показывать рядом с длительностью `HH:MM:SS:FF` (NDF), если FPS известен;
     иначе `HH:MM:SS.mmm` и подсказку «FPS не определён».
   - FPS брать из `QMediaPlayer.metaData()` (`VideoFrameRate`), поддерживать
     23.976, 24, 25, 29.97, 30, 50, 59.94, 60.
   - Не менять текущий формат `format_ms` для статусов буферизации; добавить
     отдельную функцию `format_timecode(ms, fps)`.
2. **Покадрово.**
   - Клавиши `,` и `.` — на один кадр назад/вперёд; кнопки `−1 кадр`/`+1 кадр`
     в панели.
   - Перед шагом ставить паузу; шаг равен `1000/fps` мс (при неизвестном FPS —
     40 мс).
   - Текущие `←`/`→` (5 сек) и `Shift+←/→` (1 сек) не ломать.
3. **J/K/L.**
   - `L` — play, `K` — pause, `J` — шаг назад (если QtMultimedia не умеет
     реверс, не эмулировать реверс покадрово; достаточно шага назад).
   - Повторное `L` — скорость 2x/4x/8x, `K` — сброс на 1x. Показывать скорость
     в статусе.
4. **In/out.**
   - `I` — поставить in, `O` — out; отметки на слайдере уже есть
     (`SeekSlider.set_marks`);
   - показывать длительность фрагмента;
   - «Играть фрагмент» использует существующий `play_range`;
   - «Сбросить in/out»;
   - отметки сбрасываются при открытии другого файла и не сохраняются на диск.
5. **Экспорт кадра.**
   - Кнопка «Кадр PNG»; сохранять текущий кадр без элементов интерфейса.
   - Основной путь: `QVideoSink.videoFrame()` → `QImage` → PNG.
   - Если кадр недоступен: ffmpeg `-ss <sec> -i <url> -frames:v 1` во временный
     файл, с теми же заголовками, что у превью; прогресс/ошибка.
   - Имя по умолчанию: `<имя_файла>_HH-MM-SS-FF.png`; предложить папку
     загрузок, не перезаписывать без подтверждения.
   - После сохранения — уведомление с кнопкой «Открыть папку».
6. Для аудио и изображений покадровые кнопки/таймкод скрывать; для видео без
   известного FPS — оставлять миллисекунды.
7. Не ломать сценарий соцсетей: `set_marks`/`play_range` используются там же.

**Приёмка:**

- 25 fps: 1 секунда = 25 кадров, таймкод `00:00:01:00`;
- 23.976/29.97/30 fps — корректный таймкод без отрицательных кадров;
- шаг вперёд/назад меняет позицию ровно на кадр;
- in/out и «Играть фрагмент» работают;
- экспорт PNG совпадает по размеру кадра и не содержит UI;
- неизвестный FPS не роняет плеер;
- аудио/фото не показывают лишние кнопки;
- существующие тесты превью и соцсетей зелёные.

## 10. Риски и открытые вопросы

**Риски:**

- сертификат подписи: стоимость, срок выпуска, репутация SmartScreen;
- замена файлов запущенного PyInstaller-приложения и блокировки антивирусом;
- `QMediaPlayer` может не отдавать FPS для некоторых контейнеров;
- экспорт кадра через `QVideoSink` может дать чёрный кадр для отдельных кодеков;
- поиск только по загруженным узлам может не оправдать ожиданий;
- кэш листингов может показывать устаревшие данные;
- случайная утечка секретов в диагностику;
- Excel и разделитель `;`/BOM на разных локалях;
- GitHub может быть недоступен у части пользователей.

**Открытые вопросы к согласованию:**

1. Сертификат: OV или EV, кто оформляет, бюджет.
2. Установщик: Inno Setup или MSIX; per-user — подтверждаем?
3. Нужен ли зеркальный источник обновлений помимо GitHub?
4. Поиск: только по загруженному дереву — согласовано?
5. Диагностика: только ручная отправка, без загрузки на сервер?
6. Отчёт CSV: все задания или только завершённые?
7. Выход из аккаунта: очищать ли кэш превью провайдера?
8. Нужен ли P1 «Скачать и выключить ПК» в 1.0?
9. Кто утверждает тексты ошибок и подсказок для монтажёров?
